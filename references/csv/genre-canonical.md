# 题材权威枚举表（Genre Canonical List）

> 状态：`active`
> 数据来源：番茄小说排行榜实际分类（2026-04 抓取）

## 设计目标

建立一套两层题材体系，让 CSV 的 `适用题材` 列、`references/taxonomy/genre-index.csv` 与 `reference_search.py --genre` 有统一的枚举值可以对齐。

**题材在本插件里只是分类标签**：它决定检索时按哪个 `适用题材` 过滤，不携带任何写法处方、调性预设或套路配方。插件不提供题材模板、爽点公式或桥段库。

## 题材 vs 套路：核心区分

**题材**回答"故事发生在什么世界"——都市、玄幻、仙侠、古言……

**套路**回答"用什么模式讲故事"——退婚、系统、无限、重生、赘婿、快穿任务……

同一个套路可以跨题材：系统流可以在玄幻里，也可以在都市里。因此所有"X流"（退婚流、系统流、无限流、赘婿流、重生流、副本流……）**不是题材**。

插件不为套路提供任何数据表——套路属于作者的创作选择，写在本轮要求或 `设定集/文风提示词.md` 里。当用户输入"我要写退婚流"时，插件只做题材判定：退婚流最常见于传统玄幻 → canonical_genre = `玄幻`；"退婚"本身作为别名参与识别，但不会带出任何桥段处方。

`references/taxonomy/genre-index.csv` 的 `aliases` 与 `trope_tags` 列可以包含套路名作为识别入口，`canonical_genre` 列只填 15 值枚举之一。

---

## 两层结构

```
Layer 1: canonical_genre  （15 个，我们定义）
    ├── 用于 references/csv/ 三张一致性表的 `适用题材` 列
    ├── 用于 references/taxonomy/genre-index.csv 的 `canonical_genre` 列
    └── 用于 reference_search.py 的 --genre 筛选

Layer 2: platform_tag  （番茄原始分类）
    ├── 用于 genre-index.csv 的 `label` 列（label_type=platform）
    ├── 用于 genre-index.csv 的 `aliases` 列（输入识别，可含套路名以提升命中）
    └── 每个 platform_tag 映射到且仅映射到一个 canonical_genre

不属于题材体系、且插件不提供数据的概念：
    - 套路/模式（退婚、系统、无限、重生……）→ 作者自定义，插件不提供套路表
    - 调性标签（爽文、深度剧情、现实向……）→ 作者写入 设定集/文风提示词.md
    - 场景写法、爽点、节奏、桥段 → 交给模型与作者，插件不提供技法表
    - 形式标签（短篇、互动小说……）→ 只作 format_tags 记录，不影响检索
```

**规则**：
- `适用题材` 列只允许填写 canonical_genre 枚举值或 `全部`
- `genre-index.csv` 的 `label` 可以是 canonical 或 platform 级别，由 `label_type` 区分
- 用户在 init 阶段输入任意文本 → `resolve_genre_input()` 先匹配 label/aliases → 再映射到 canonical_genre
- 一个 canonical_genre 可以对应多个 platform_tag，但一个 platform_tag 只归属一个 canonical_genre
- 套路名可以出现在 `aliases` / `trope_tags` 列用于识别，但不作为题材枚举值，也不带出任何写法处方

## 与现有 CSV 的对齐规则

### 1. `适用题材` 列（三张一致性表：命名规则 / 人设与关系 / 金手指与设定）

- 只允许填写 canonical_genre 枚举值（上述 15 个）或 `全部`
- 多值用 `|` 分隔：`都市|玄幻|仙侠`

### 2. `references/taxonomy/genre-index.csv`

- `canonical_genre` 列只填 canonical_genre 枚举值或 `全部`
- `label` 列可以是 canonical 或 platform 级别，由 `label_type` 区分
- `aliases` 列填该 label 的所有别名（可含套路名以提升识别命中）
- `route_tags` / `trope_tags` / `format_tags` 只作为标签记录写入 `project_info.genre_tags`，不参与检索过滤，也不带出写法处方

### 3. `reference_search.py --genre` 参数

- 接受 canonical_genre 或 platform_tag
- 如果输入是 platform_tag，先映射到 canonical_genre 再做筛选
- `_genre_matches()` 用 canonical_genre 匹配 CSV 中的 `适用题材` 列

### "删除"的处理

标记为"删除"的值不是说条目要删——而是该条目的 `适用题材` 需要改填实际的 canonical_genre，或改为 `全部`。

例如：一条标注 `适用题材=狗血` 的人设条目，应该改为 `适用题材=现言|古言`（如果它只适用于言情类）或 `全部`（如果它跨题材通用）。
