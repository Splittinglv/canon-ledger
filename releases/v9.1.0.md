# v9.1.0 - HEAD-bound 可选向量召回

## 发版范围

发布日期：2026-08-28

本次发布覆盖 `v9.0.0..v9.1.0`。它补回长篇小说所需的语义召回，但把检索严格放在
Canon v3 事实权威之后：索引可以删除、过期或失败，正史与写作门禁不受它控制。

## 给作者看的变化

### 长篇事实更容易找到

- 新增 `canon-v3 retrieval status|rebuild|search`，可以用语义向量或本地 BM25 定位
  角色知识、物品持有、关系、规则、承诺和开放问题等 active facts。
- Context 会把与本章目标相关的命中作为提示，Reviewer 可用它寻找 prior facts，宽泛查询
  也可先检索再走精确 v3 facade。所有命中都携带已回查的 `active_fact`，相似文本本身不是证据。

### 失败不阻断写作

- 远程 Embedding 默认关闭；只有 `CANON_LEDGER_RETRIEVAL_REMOTE=1` 与非空
  `EMBED_API_KEY` 同时满足才会发送检索文本。仅有 key、远程失败、部分向量、索引缺失、
  过期或损坏时都使用本地 BM25，且不改变 `state=ready`、人工决定或章节完成状态。
- 历史 as-of 查询使用对应 Canon 快照，不会把未来章节事实带回旧章。
- 旧 `rag` 与 `.canon-ledger/vectors.db` 继续退役；它们即使存在也不会进入当前 Context、
  Reviewer、Query、Doctor 或 Dashboard。

### 权威边界

- 检索库只复制当前 `active_canon`，排除 STAGING、style、未认证设定草稿、legacy 和失效历史。
- 库同时绑定 HEAD、generation、workflow、author-axiom、Canon projection 与 active fact set。
  HEAD 前进、事实删除/替换或内容被篡改后，搜索会忽略旧库并从当前快照降级召回。
- 检索命中标记 `usable_as_canon=false`；无命中不能解释为“没有发生”。

## 安装方式

新安装继续按 README 将仓库作为本地 Cursor 插件载入，并安装 Python 与 Dashboard 依赖。
升级现有项目后先运行：

```bash
python3 -X utf8 "<PLUGIN_ROOT>/scripts/canon_ledger.py" \
  --project-root "<PROJECT_ROOT>" canon-v3 status
python3 -X utf8 "<PLUGIN_ROOT>/scripts/canon_ledger.py" \
  --project-root "<PROJECT_ROOT>" canon-v3 retrieval rebuild
```

第二条是可选增强，失败不影响 Canon。默认只使用本地 BM25。确认允许远程发送后，在书项目
`.env` 同时设置 `CANON_LEDGER_RETRIEVAL_REMOTE=1`、`EMBED_BASE_URL`、`EMBED_MODEL` 与
`EMBED_API_KEY`；端点必须兼容 OpenAI `/v1/embeddings`。仅设置 key 不会启用远程，项目
`.env` 的 `CANON_LEDGER_RETRIEVAL_REMOTE=0` 可覆盖全局同名 `=1`。启用后 active Canon 的
检索文本会发送到该服务，请自行评估作品保密要求。

Write/Confirm 发布后自动尝试的 rebuild 也遵守该开关。`--bm25-only` 只控制一次重建且会
复用已有向量；单次搜索的 `mode=bm25` 只控制该次查询。需要整本书持续本地运行时，应保持
`CANON_LEDGER_RETRIEVAL_REMOTE=0`。

## 给维护者

- 唯一检索投影为 `.story-system/v3/projections/retrieval.sqlite3`，重建采用固定路径、临时库、
  authority 复查和原子替换；已存在且内容未变的同模型向量可精确复用。
- search 请求使用 strict `canon-v3/retrieval-search-request/v1`，只从项目内
  `.canon-ledger/tmp/*.json` 消费；CLI、Hook 与 runtime 各自校验 capability/path。
- 每个索引行包含 active fact 内容摘要并在读取时完整验证，命中后再与当前 fact set 对齐。
- Dashboard 只增加 GET status，不提供检索写路由；Doctor 的 retrieval warning 永远不覆盖
  workflow 的唯一 `primary_action`。
- Rerank 配置仅为兼容保留，当前 v3 retrieval 不调用它。
