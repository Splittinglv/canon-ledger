# v6.2.1 - 写到几百章，也只守事实、不替作者规定文风

## 发版范围

这是本仓库首个正式 Cursor 移植基线，版本沿用上游引擎 `v6.2.1`。它覆盖当前 `main` 中长期一致性、事实检索、写章绑定和运行安全的完整实现。

## 给作者看的变化

- 初始化只记录作者明确给出的题材和设定，不再自动套入退婚流、追妻火葬场等题材处方，也不会凭空创建“未命名金手指”。
- 写前上下文会完整带上仍生效的世界规则、人物关系、未回收伏笔和未兑现承诺；软性历史证据才会按预算裁剪。
- 向量模型可用于跨章事实召回；没有 Embedding Key 时自动使用本地 BM25，检索能力可降级但写章不会被卡住。
- 审查、事实抽取、提交、投影和备份都绑定最终正文。正文改动后必须重新审查和提交，旧产物不会继续生效。
- 默认上下文不注入文风、句式、节奏或桥段建议。作者可以在书项目的 `设定集/文风提示词.md` 中自行定义，也可以直接使用当前模型的默认文风。

## 是否需要改旧项目

不需要手工修改正文或设定。旧项目第一次进入新的严格写章流程时，无正文绑定的历史提交会被标记为旧格式，需要对相关章节重新审查、抽取并提交；旧检索索引可按诊断提示重建。

## 给维护者

- 题材初始化、记忆投影、RAG、正文绑定和硬约束上下文均有独立回归测试。
- 投影写入支持选择性重试、按字段版本保护、生命周期墓碑和时间线稳定顺序。
- RAG 仅信任与已接受 commit 匹配的事实快照，支持语义检索与 BM25-only 存储。
- Cursor hooks 对受保护运行时状态采用 fail-closed；Skill 环境加载使用 JSON 数据协议，不执行导出器输出。
- 发布脚本同时支持根级 `.cursor-plugin` 和旧版嵌套 `.claude-plugin` 布局。
