# v6.2.2 - 长篇事实能重建，文风仍由作者决定

## 发版范围

本次发布覆盖 `v6.2.1..v6.2.2`。它修复长期一致性真源、设定写回、章纲门禁、同章修订、审查、备份恢复和 Cursor 运行安全链路。

## 给作者看的变化

- 初始化时明确提供的人物、世界、势力、力量体系和限制会从首章进入一致性上下文。
- 规划后写回 `设定集/*.md` 的结构化事实会生成可校验快照；设定改了却没有刷新时会阻断写章，不会假装“上下文完整”。
- 写第 N 章只使用正文绑定且已接受的前 N-1 章事实。人物状态、关系、时间线、伏笔、承诺与一般事实不会被未来章节污染。
- 同一章改稿后，旧事件、旧状态、旧场景和旧检索内容会被替换，并从当前全部提交重建；投影失败不会安装半套数据。
- 章纲目标、关键实体、时间信息、必达节点、禁区、未闭合问题和钩子会完整落入章合同。现代项目缺合同、空目标或用空清单冒充完成都会被阻断。
- 世界规则必须有本章正文的逐字证据。章节节奏、反转频率、悬念和爽点等创作配方不会进入硬约束。
- 审查模式现在是明确的完整审查、快速审查或最简跳过；插件不再替作者评价文笔、节奏或“AI 味”。
- 没有 Git 时，本地备份会保存正文、大纲、设定集、Story System 和必要运行状态，并验证签名文件清单后再恢复。

默认写作包仍只提供长期事实一致性。具体文风、文笔、句式、叙事节奏与创作手法继续由当前模型、本轮用户要求或 `设定集/文风提示词.md` 决定。

## 是否需要改旧项目

不用改正文。旧项目第一次进入新流程时，如果历史提交没有正文绑定、章合同缺少目标，或设定文件尚未生成同步快照，插件会给出明确阻断原因。按提示重新刷新 Story System、重新审查并提交相关章节即可；读模型可以通过 `projections replay` 重建。

旧版没有 Story System 的纯兼容项目仍可读取，但不会把没有正文证据的自由文本世界规则提升为硬约束。

## 给维护者

- canonical history 从正文绑定的 accepted commits 重放，默认历史时点是目标章前一章。
- 同章提交采用隔离 staging、完整投影重建、验证后原子安装和失败回滚。
- 设定快照记录来源路径、字节数与 SHA-256，只接受结构化事实并排除文风文件与创作处方。
- review artifact 使用闭合维度和问题 schema；提交与报告链不再接受伪完整审查。
- 本地备份使用项目内 HMAC 完整性密钥、逐文件 manifest、救援快照与恢复后投影重建。
- Hook 统一选择可导入依赖的 Python，拒绝未受信脚本执行和受保护状态写入，并保留真实 Skill 只读与统一 CLI 工作流。
- 发布校验要求已有版本 tag、版本递增、干净工作区、同步 manifest 与作者可读说明。
