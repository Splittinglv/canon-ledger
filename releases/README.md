# CanonLedger 发行说明模板

每个正式版本必须有 `releases/vX.Y.Z.md` 和 `CHANGELOG.md` 当前版本小节。发行说明先写作者能感知的改变，再记录维护者协议与验证。

`<PREVIOUS_TAG>` 必须：

- 是真实存在的 `vX.Y.Z` tag；
- 指向当前 `HEAD` 的祖先；
- 是低于目标版本的、当前 `HEAD` 可达的最高 SemVer tag。

目标 `vX.Y.Z` tag 可以在校验时尚未创建；只有文档、版本同步、测试和严格包校验通过，且发布提交后工作区干净时，才应将目标 tag 创建在当前 `HEAD`。

## 固定模板

```markdown
# vX.Y.Z - 一句中文作者收益

## 发版范围

本次发布覆盖 `<PREVIOUS_TAG>..vX.Y.Z`。

## 给作者看的变化

- 用作者能理解的故事、正文、设定、伏笔或写章场景描述变化。

## 安装方式

说明新安装方式、现有项目是否需要备份/迁移，以及 breaking change 的恢复动作。

## 给维护者

- 记录协议、数据、安全和兼容性边界。

## 验证

- 记录实际执行的测试、行为评估和发布校验。
```

## 发布前检查

1. 确认上一个 tag 存在、可达且没有跳过更高的可达 SemVer tag。
2. 同步 manifest、marketplace 与 README 版本面。
3. 补齐当前 `CHANGELOG.md` 小节和本版本发行说明。
4. 运行测试、行为评估、版本同步、严格插件包与发行说明校验。
5. 提交发布变更，在干净的当前 `HEAD` 创建并推送目标 tag。
