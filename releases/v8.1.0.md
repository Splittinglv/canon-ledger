# v8.1.0 - 长期事实边界、恢复与公开协议全面收口

## 发版范围

本次发布覆盖 `v8.0.0..v8.1.0`。

## 给作者看的变化

- 插件只守长期客观事实。文风、文笔、节奏、动机、性格、人设、成长弧、剧情选择和章纲履约只是作者与当前模型的可自定义输入，不进 Canon 强制门禁。
- 新建项目改为 clean-target-only 隔离发布；已有内容、v3、legacy、malformed 或 symlink 目标不会被 init 覆盖。
- 关键事实与实质歧义继续默认人工介入。公开 case 会直接返回有序 `allowed_actions` 和 exact decision binding，不再要求 Skill 猜动作矩阵。
- 作者可在 Confirm Skill 中明确放弃当前未发布事务。插件按最新 stage digest 归档指针、保留证据对象，旧 finalize 不能继续。
- 章纲可通过 planning-only facade 刷新卷/章/审查合同，但不会进 HEAD 或变成履约 blocker。规划中新增永久硬规则有独立运行时 schema/validator 与 author-axiom 人工发布链。
- 历史章默认只读审计；新发布章的 exact 正文会在 HEAD 切换前归档。导出不读 STAGING、Git、legacy index 或未来事实，没有可验证字节时明确报 `source_unavailable`。
- Doctor 和 Dashboard 不再把缺少大纲、规划合同、legacy index/RAG 当成正史 blocker；事实可用性只看 exact workflow 和 HEAD-bound fresh projection。
- 存量 v2/author-axiom 若夹带文风、动机或人格等软内容会保持只读，直到作者完成 exact supersession；污染投影不会继续用于写章。

## 安装方式

新安装按 README 将仓库作为本地 Cursor 插件载入，并安装
`scripts/requirements.txt` 与 `dashboard/requirements.txt`。本仓库是 Cursor 插件，不需要
也不会新增 `.codex-plugin` manifest。

升级现有书项目前先备份。8.0 的 v2 genesis 仍可按原语义读取，不会被新边界静默
改写；使用下述只读分析决定是否做完整 author-axiom supersession 或 clean-target
fork。不要用 init 覆盖旧项目，也不要直接删 STAGING/对象库来解除冲突。

### 存量 v8 项目升级

新 cutover 使用 `legacy-genesis/v3 + legacy-fact-snapshot/v3`，已知软设计只留审计 receipt，不进 active facts。旧 `legacy-genesis/v2` 必须保持原字节解释，因此不会在升级时被静默重写。

对 v2 CURRENT 运行 `canon-v3 audit-cutover` 或 `repair-cutover --dry-run`，读取 `fact_boundary_analysis`：

- `clean`：没有需要移除的旧软 admission。
- `human_classification_required`：自定义叶子需作者判断，保持只读。
- `ready_to_supersede`：可将 override fragment 合并进保留全部当前 author-axiom records 的完整 proposal；fragment 不是整份请求。
- `manual_fork_required`：存在活动下游引用，禁止原地 supersede；保留原项目只读，在 clean target fork/rebuild。

author-axiom prepare 和 finalize 都在 CURRENT CAS 前复查下游依赖，不能通过并发变化留下悬空后缀。
除 `clean` 外，workflow 固定为 `migration_required`，公开 query/context 也拒绝消费旧投影。
旧 active author axiom 的软 key/category/value 使用独立只读状态和 exact 人工 remove 事务；
新 proposal 在 validator、prepare、decision、finalize 四处复用同一事实边界。

## 给维护者

- 章节、author-axiom 和 legacy recertification 共用 typed public action registry/serializer，不修改已持久对象的 digest schema。
- 公开 query/history/as-of 只读 HEAD-bound 净化视图，携带活动 author-axiom 语义与可用 source，查询前后复查权威版本；同名实体明确返回人工消歧状态。
- status/query/Doctor/Dashboard 移除读取时 lock/mkdir 副作用。
- `archive-staging` 使用 transaction kind + exact stage digest，原子移动 pointer，保留不可变对象并支持 exact idempotent replay。
- planning facade 对输入、HEAD 和三份合同共同批次摘要做绑定；historical export 完整导出可达 commit/transaction/decisions/lineage 和当时权威。
- Reviewer v3 绑定 exact candidate ID→digest map；assembler 拒绝 ID 互换和重复语义 digest，不改持久化 candidate digest schema。
- CLI/Hook 共用 closed command policy，拒绝所有 legacy adapters、backup/archive 与旧状态写入口；Rule 覆盖正文 glob，严格包校验增加对应 mutation tests。
- POSIX/PowerShell 统一转发 `run_acceptance.py`；full 验收审计当前权威测试确实被收集，同时保留明确冻结的 retired-v2 规格。
