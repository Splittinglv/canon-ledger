# v8.0.0 - 正史写入统一为可验证、可确认的 Canon v3 事务链

## 发版范围

本次发布覆盖 `v7.2.0..v8.0.0`。

## 给作者看的变化

- 每章只有一条正史写入链：候选事实先绑定真实正文或作者硬设定，通过五维完整扫描，再经 `prepare → decide → finalize` 进入正史。模型不能直接改状态、关系、时间线或伏笔。
- 人物、物品、地点、持有人、前后状态等每个字段都必须有它自己的证据。引文只是“出现过”却不支持实际声明时，不会被写进正史。
- 核心角色永久状态、重大关系、世界硬规则、关键物品、核心秘密等 checkpoint 必须由作者批准或选择重写。真正歧义可批准、省略、修正或重写，但无法用旧选择偷换新候选。
- 人物/组织、物品、地点使用独立身份命名空间；首次身份、新别名和同名多实例需要显式确认，不会默认合并到第一个同名对象。
- 状态更新、知识、在场、持有、承诺、伏笔、时间和规则违反统一绑定旧事实谱系。重复 prepare、重放旧决定或换一段引文，不会让已省略/重写/修正的候选悄悄复活。
- 命令、Skills、Dashboard、写前门禁和报告统一显示 workflow 状态与唯一恢复动作。只有 `ready`、`can_write_next=true` 且投影已跟上正史时才能继续下一章。
- 章纲是剧情方向，不是“已发生事实”。规划中新增的长期硬设定经 author-axiom 确认链生效；文风、文笔与章纲履约仍由作者和当前模型决定。

## 安装方式

新安装按 README 将仓库作为本地 Cursor 插件载入，并安装 `scripts/requirements.txt` 与 `dashboard/requirements.txt` 中的依赖。

8.0 以前的 v2/legacy 项目不能直接继续旧写链。升级前先备份书项目，用 `canon-v3 status` 查看当前边界，再按 README 执行 `migrate --cutover-chapter K`。首次 cutover 有无法证明、未分类或身份冲突的输入时会直接失败，必须先修复旧来源再重跑。已有 CURRENT 的冻结 legacy prefix 若失绑，只运行 snapshot 指向的只读 `audit-cutover`，由作者恢复来源或显式重建后缀；普通 migrate 不会覆盖 stale CURRENT。仅 `canon-v3/legacy-genesis/v1` 走 detached recertification；未发布的 v1 STAGING 返回 `recompile_required` 并按当前 schema 重新 prepare。旧 HEAD 与对象保留只读，修复链全部通过后才原子切换。

## 给维护者

- 正史使用内容寻址的 immutable commit/manifest、`CURRENT` CAS 切换与同 HEAD 投影绑定；派生投影可删除重建，不能反向成为事实来源。
- `canon-v3/proposal-batch/v2` 只接受 typed candidates、observations 和 attestations；每个非空 claim 字段通过 `support_map` 绑定经验证 SourceRef。
- Active Slot Registry 为跨章更新绑定 `prior_fact_digest`，为同章连续变化绑定 `prior_effect_id`；承诺兑现与伏笔关闭必须命中 active prior。
- 决定请求和 finalize token 绑定 exact stage/transaction/material/target/decision head、正文 SHA、candidate/effect/source、父 HEAD 与 policy；任一变化都会拒绝旧操作。
- legacy migration 将旧 event/delta/timeline/entity 转成 typed candidates 并留下 admission、identity、slot transition 与 normalized fact receipt；无法证明、未分类或身份冲突的初次 cutover 输入 fail closed，不创建带事实洞的 CURRENT。
- CLI、write gate、报告、context、Skills 与 Dashboard 统一消费 `canon-v3/workflow-snapshot/v2` 及 `workflow_digest`，无 CURRENT 时不回落 legacy。
