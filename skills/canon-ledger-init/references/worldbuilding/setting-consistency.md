# 长期事实自洽参考

> 仅在用户明确需要世界规则或事实建模帮助时读取。它不是写作评分表，也不检查人物动机、行为合理性、剧情取舍、章纲完成度或文风。示例只是候选，不能未经作者确认写入 Canon。

## 需要长期记住的事实

优先整理后文会直接依赖、且能用明确字段表达的内容：

- 世界规则及其已声明的例外、前提和代价；
- 角色身份、永久状态、知识边界和真实在场；
- 物品身份、持有关系、损毁或消耗状态；
- 有明确锚点的时间、倒计时和先后顺序；
- 已建立的关系、承诺和开放问题。

作者没有确定的值可以留空。不要为了“完整”制造力量等级、物价、势力数量、升级代价或角色性格。

## 可选的结构化草案

用户希望设计硬规则时，可用下面的最小形式起草：

```markdown
## 规则名称
- 适用对象：
- 明确规则：
- 前置条件：
- 已确认例外：
- 代价或冷却：
- 来源：作者本轮说明
```

时间事实可以用：

```markdown
| 事件 | 明确时间锚点 | 与其他事件的顺序 | 来源 |
|------|--------------|------------------|------|
|      |              |                  |      |
```

这些草案仍不是 active Canon。初始化时只有 closed `MASTER_SETTING.initial_canon`
里的明确身份与硬规则进入 genesis；后续新增、修改或删除长期硬设定必须生成 managed
author-axiom draft，并由作者逐项决定后 finalize。

## 写后事实检查边界

章节完成后只问证据能支持的问题：

- 本章陈述是否与 active HEAD 中的明确规则或永久状态不能同时成立？
- 角色是否使用了 active HEAD 表明其尚未知晓或已经遗忘的信息？
- 在场、持有、时间锚点或状态转换是否出现明确冲突？
- 正文明示的长期事实是否被候选完整提取？

系统拿不准但有正文锚点时转人工；无锚点、极低概率的猜测直接忽略。角色“为什么这样做”、战斗“是否精彩”、社会结构“是否足够合理”等属于作者与模型的创作判断，不是默认事实门禁。

## 修订既有事实

发现真实冲突时，不直接改投影、`state.json`、`index.db` 或设定文件来掩盖。正文冲突走 `rewrite` 并重建 candidate；作者主动修订硬设定走 author-axiom add/update/remove。活动事实始终以 Canon v3 HEAD 为准，投影只可从同一 HEAD 重建。
